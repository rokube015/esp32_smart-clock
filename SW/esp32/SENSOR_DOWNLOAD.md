# IO4ボタンでセンサCSVを取得する

SW4はIO4とGNDを接続するボタンです。内部プルアップを有効にし、
押したときのLOWを検出します。20ms間隔で読み取り、40msの安定時間で
チャタリングを除去します。長押しは1回の押下として扱います。

ボタンの読み取りと押下判定は `components/button` の `BUTTON` コンポーネントが担当します。
`BUTTON::Event` をFreeRTOSキューでSMART_CLOCKへ送信し、SMART_CLOCKの
ネットワーク管理タスクがイベントを受信してWi-Fi接続とCSVサーバーを管理します。
SMART_CLOCKがボタン監視タスクとネットワーク管理タスクを起動します。
`main.cpp` からGPIOを読み取ったりWi-Fi処理をポーリングしたりする必要はありません。

押下・受信ログ：

```text
button: IO4 pressed; sending PRESSED event
smart_clock: IO4 button pressed; enabling sensor downloads for 5 idle minutes
```

1. ESP32とWindowsを同じLANに接続できるよう、従来のWi-Fi設定を済ませます。
2. SW4を押します。保存済みの設定でWi-Fiに接続します。
3. 電子ペーパー画面下部、または起動ログに表示される
   `http://<ESP32のIPアドレス>:8080/` をWindowsのブラウザで開きます。
4. 「センサ記録CSVをダウンロード」をクリックします。

PowerShellから直接保存することもできます。IPアドレスは置き換えてください。

```powershell
Invoke-WebRequest -Uri 'http://192.168.1.123:8080/sensor_log.csv' -OutFile '.\sensor_log.csv'
```

ボタン押下、HTTPリクエストの開始・終了から5分間操作がないと、
HTTPサーバーとWi-Fiを停止します。転送中は停止を延期します。
ボタンを再度押すと利用時間を延長できます。
Wi-Fi接続に失敗した場合も、ダウンロードモードは5分で終了します。
ただし、Wi-Fi設定用のプロビジョニング中は、設定を完了できるよう停止しません。

従来の起動時・日付変更時の時刻同期は維持します。
ボタンでダウンロードモードに入っている間は、時刻同期が完了してもWi-Fiを停止しません。
通常の時刻同期だけではCSVサーバーを起動しません。

取得するのはSDカードの既存の `/sdcard/sensor_log.csv` です。
取得開始時点のファイルサイズまでを1KBずつ送信し、取得中の追記は次回の取得に含めます。
ネットワーク通信中はSDカードのロックを解放し、センサ記録を継続します。
SDカードが利用できない場合はHTTP 503、記録ファイルがない場合は404を返します。

認証・暗号化はありません。信頼できるLAN内で利用してください。
端末間通信を禁止するゲストWi-Fiではアクセスできません。

## 測定と時計表示の同期

センサの約60秒周期の取得が完了してから、時計表示タスクへ更新を通知します。
独立した画面更新タイマーは廃止し、更新直前の古い測定値が1周期残る問題を解消します。
取得失敗の場合も更新を通知し、無効な値の表示状態を更新します。
ボタン・Wi-Fi・時刻同期による画面更新は維持します。
全タスクの作成完了後に開始ゲートを解放し、初回測定・表示通知を取りこぼさないようにします。
Androidはsequenceで更新を待ち、有効な結果が同じ間は最大約1秒待ってHTTP 204を返します。
通信遅延と電子ペーパーの描画時間による表示の差は残ります。

CSV記録は測定結果確定時にだけ行い、表示通知では追記しません。
測定時刻・SD・両センサが有効なsequenceについて追記を一度だけ試みます。
書き込み失敗または対象外の測定を後から再記録しません。
片側センサの失敗時も、正常なもう片側は表示し、失敗側は `--` とします。
最新値APIは全項目有効時だけ従来のJSONを返し、無効時はHTTP 503を返します。

起動時・日次の時刻同期は接続開始から5分で期限切れとし、失敗後30分に再試行します。
同期完了・期限切れでもボタン利用中やHTTP転送中はWi-Fiを維持します。
プロビジョニング中も期限による停止は行いません。
詳しい構成と変更ファイルは [ソフトウェア構成](SOFTWARE_ARCHITECTURE.md) を参照してください。
